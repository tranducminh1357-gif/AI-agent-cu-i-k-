Doanh nghiệp mục tiêu: SME Bán lẻ, TMĐT & Đa ngành
Doanh Nghiệp Mục Tiêu & Bài Toán Vận Hành

Các doanh nghiệp SME (chuỗi cửa hàng, bán lẻ đa kênh, dịch vụ) vận hành song song nhiều nguồn dữ liệu: Bán hàng POS/TMĐT, Kho hàng, Chấm công HR, và Sổ kế toán.

Bài toán đặt ra: Cần một AI Agent tự động đọc hiểu mọi cấu trúc bảng dữ liệu bất kỳ, làm sạch lỗi, tra cứu đúng công thức nghiệp vụ và xuất báo cáo chuẩn xác không sai số.

4 Nỗi Đau Thực Tế Khi Vận Hành Thủ Công / AI Thường
  • 1. Dữ liệu thô hỗn loạn: File CSV/Excel lỗi delimiter, ngoặc kép chưa đóng (ERR-001,"Website,100000), trùng lặp, null hoặc sai kiểu số.
  • 2. Tốn thời gian tổng hợp: Nhân sự mất 4–8 giờ/tuần để lọc, ghép bảng và tính tay P&L theo Thông tư 200.
  • 3. Rủi ro AI "bịa số liệu": LLM thuần túy tự đoán công thức hoặc bịa doanh thu/lợi nhuận âm sai lệch với dữ liệu gốc.
  • 4. Thiếu linh hoạt đa miền: Công cụ cứng nhắc chỉ đọc được file doanh thu, bó tay trước file chấm công hoặc danh mục hàng hóa.
Mục tiêu giải pháp: Xây dựng TienBrystudio — tách biệt hoàn toàn lớp Tính toán xác định (Deterministic Script Engine) và lớp Suy luận ngôn ngữ (LLM), có điểm dừng HITL để đảm bảo 0% bịa đặt số liệu.
Trang 2 / 6 (Nội Dung Chính)

Kiến Trúc Agent Blueprint (GIWO)

Goal → Input → Workflow → Output
1. GOAL (Mục tiêu)

Xác định tên DN, ngành nghề, mục tiêu phân tích (BCTC VAS, Tồn kho, Chấm công HR, CRM) và chuẩn công thức áp dụng.

2. INPUT (Đầu vào)

Nạp file .xlsx, .csv, .json hoặc Paste thô. Tự tách dấu phân cách & sửa ngoặc kép lỗi.

3. WORKFLOW (Tác tử)

Phân rã nhiệm vụ: Profile Schema → Làm sạch ETL → Kiểm toán bất thường → HITL Approval Gate → Tổng hợp AI.

4. OUTPUT (Đầu ra)

Dashboard đa miền, BCTC Thông tư 200, Báo cáo Markdown (.md) có cấu trúc, Excel/CSV sạch & AI Chat hỏi đáp.

4 Hàng Rào An Toàn Bắt Buộc (Mandatory Guardrails)
Zero-Fabrication Guardrail: Cấm LLM tự tính nhẩm hoặc điền số ước lượng; mọi KPI lấy trực tiếp từ CURRENT_DATA đã kiểm chứng.
Strict Status Matching: Dùng isCompletedStatus() / isReturnStatus() tránh lỗi substring làm âm doanh thu.
Formula Knowledge Base: Agent tra cứu công thức chuẩn (VAS 200, Tồn kho, HR) trước khi giải thích cho người dùng.
HITL Approval Breakpoint: Khóa xuất báo cáo cuối nếu người dùng chưa phê duyệt bảng kiểm toán làm sạch ở Bước 4.

Cơ Chế Kiểm Soát & An Toàn (HITL & MCP)

Human-in-the-Loop + Bảo Mật Kết Nối
Điểm Dừng Phê Duyệt Con Người (HITL Breakpoint)
Bước 1–3: Agent tự động nạp file, sửa delimiter và kiểm toán ngoại lệ.
APPROVAL BREAKPOINT (Bước 4): Agent TẠM DỪNG, hiển thị tổng số dòng sạch, số dòng bất thường/trùng lặp, và bảng ánh xạ cột để người dùng xác nhận.
Chỉ khi nhấn "Phê Duyệt & Xuất Báo Cáo": Agent mới mở khóa Bước 5 để sinh Dashboard & Markdown.
Phương Thức Kết Nối Dữ Liệu (MCP & API Proxy)
  • 1. Local Data Connector (MCP-style Tooling): Đọc trực tiếp Excel (SheetJS), CSV, JSON và Clipboard trên sandbox trình duyệt — không upload file nhạy cảm của doanh nghiệp lên máy chủ ngoài.
  • 2. Serverless API Gateway (api/chat.js): Gọi mô hình Gemini/OpenAI qua Vercel Serverless Function với biến môi trường bảo mật, chống lộ API Key ở frontend.
  • 3. Feedback Auto-Fix Channel: Người dùng báo lỗi ngay trên UI; Agent nhận ngữ cảnh + feedback để tự đề xuất và áp dụng bản sửa trực tiếp.
